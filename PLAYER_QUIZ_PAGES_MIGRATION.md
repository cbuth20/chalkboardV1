# Player Quiz Pages Migration Summary

## Overview
Migrated two player-facing pages from hardcoded team ID and deprecated API endpoints to the new organization-scoped API with custom React hooks.

## Problem
Both pages were using:
- Hardcoded `DEV_TEAM_ID` constant instead of real user context
- Deprecated `/api/get-approved-plays` endpoint
- Snake_case property names from old API
- Manual fetch calls instead of custom hooks

## Pages Migrated

### 1. Quiz Cards Page (`src/app/games/quiz-cards/page.tsx`)
**Purpose**: Browse approved plays and practice knowledge flashcards

**Backup created:** `src/app/games/quiz-cards/page.tsx.backup`

**Changes:**
- Removed `DEV_TEAM_ID` import
- Added `useAuth`, `usePlays`, and `useFlashcards` hooks
- Replaced manual fetch with `usePlays({ status: 'approved' })`
- Replaced knowledge cards fetch with `useFlashcards({ playId, cardType: 'knowledge', activeOnly: true })`
- Updated property names to camelCase (questionPrompt, correctAnswer, formationName)
- Removed unused type definitions (ApprovedPlay, KnowledgeCard)
- Updated hints display (replaced single explanation field with hints array)

**Before:**
```typescript
const [teamId] = useState<string>(DEV_TEAM_ID);

useEffect(() => {
  const response = await fetch(`/api/get-approved-plays?teamId=${teamId}&type=all`);
  const data = await response.json();
  setPlays(data.plays || []);
}, [teamId]);

useEffect(() => {
  const response = await fetch(
    `/api/get-approved-plays?teamId=${teamId}&playId=${selectedPlayId}&type=knowledge`
  );
  const data = await response.json();
  setKnowledgeCards(data.knowledgeCards || []);
}, [selectedPlayId, teamId]);
```

**After:**
```typescript
const { orgId, loading: authLoading } = useAuth();
const { plays, loading: playsLoading, error: playsError } = usePlays({
  status: 'approved'
});
const {
  flashcards,
  loading: cardsLoading,
  error: cardsError
} = useFlashcards(
  selectedPlayId
    ? { playId: selectedPlayId, cardType: 'knowledge', activeOnly: true }
    : undefined
);
```

### 2. Player Playbook Page (`src/app/playbook/page.tsx`)
**Purpose**: Browse and view approved plays with AI insights

**Backup created:** `src/app/playbook/page.tsx.backup`

**Changes:**
- Removed `DEV_TEAM_ID` import
- Added `useAuth` and `usePlays` hooks
- Replaced manual fetch with timeout handling with `usePlays({ status: 'approved' })`
- Updated property names to camelCase (formationName, aiInsights, shortName, playType, createdAt)
- Changed `playbook_metadata` to `metadata` to match new API
- Simplified error handling with useEffect for toast notifications
- Removed complex timeout/abort controller logic (now handled by hooks)
- Removed unused type definition (ApprovedPlay)

**Before:**
```typescript
const [teamId] = useState<string>(DEV_TEAM_ID);

useEffect(() => {
  const fetchApprovedPlays = async () => {
    setIsLoading(true);

    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 10000);

    const response = await fetch(
      `/api/get-approved-plays?teamId=${teamId}&type=all`,
      { signal: controller.signal }
    );

    clearTimeout(timeoutId);
    const data = await response.json();
    setPlays(data.plays || []);
    setIsLoaded(true);
    setIsLoading(false);
  };

  fetchApprovedPlays();
}, [teamId, showToast]);
```

**After:**
```typescript
const { orgId, loading: authLoading } = useAuth();
const { plays, loading: playsLoading, error: playsError } = usePlays({
  status: 'approved'
});

// Auto-select first play when plays load
useEffect(() => {
  if (!playsLoading && plays.length > 0 && !selectedPlayId) {
    setSelectedPlayId(plays[0].id);
  }
}, [plays, playsLoading, selectedPlayId]);

// Show error toast if fetching fails
useEffect(() => {
  if (playsError) {
    showToast(playsError || "Failed to load playbook. Please try again.", "error");
  }
}, [playsError, showToast]);
```

## API Dependencies

### usePlays Hook
**Source:** `@/hooks/usePlaysAPI`
**Parameters:**
- `status` - Filter by content status ('approved', 'draft', 'rejected', 'generating')
- `playType` - Optional filter by play type
- `teamId` - Optional filter by team
- `limit`, `offset` - Pagination

**Returns:**
- `plays` - Array of Play objects
- `loading` - Boolean loading state
- `error` - Error message if fetch failed
- `total` - Total count of plays
- `refetch` - Function to manually refetch

### useFlashcards Hook
**Source:** `@/hooks/useFlashcardsAPI`
**Parameters:**
- `playId` - Filter flashcards by play
- `cardType` - Filter by type ('assignment' or 'knowledge')
- `position` - Filter by position
- `difficulty` - Filter by difficulty level
- `activeOnly` - Only fetch active flashcards
- `limit`, `offset` - Pagination

**Returns:**
- `flashcards` - Array of Flashcard objects
- `loading` - Boolean loading state
- `error` - Error message if fetch failed
- `total` - Total count of flashcards
- `refetch` - Function to manually refetch

## Known Issues / Future Improvements

### Metadata Structure
The old API returned detailed `playbook_metadata` with structured fields (level, content_type, position_relevance, custom_notes). The new API uses a generic `metadata?: any` field.

**Impact**:
- Playbook page may not display metadata sections if new API doesn't return it in the same structure
- All metadata access is optional (using `?.` and `&&`), so page won't crash
- Metadata sections will simply not render if data is missing

**Future Work**:
- Verify what metadata the new API actually returns
- Update metadata structure to match new API response
- Consider creating a proper Metadata interface instead of `any`

### Hints vs Explanation
The old flashcard format had a single `explanation` field. The new format has a `hints: string[]` array.

**Current Implementation**: Quiz cards page displays all hints as a bulleted list instead of a single explanation paragraph.

**Future Consideration**: May want to add a "show hint" button that reveals hints one at a time instead of showing all at once.
