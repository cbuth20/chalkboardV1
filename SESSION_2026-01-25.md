## Migration Pattern Used

All 4 pages followed this consistent pattern:

### 1. Remove Hardcoded Constants
```typescript
// Before
import { DEV_TEAM_ID } from "@/lib/constants";
const [teamId] = useState<string>(DEV_TEAM_ID);

// After
import { useAuth } from "@/contexts/AuthContext";
const { orgId, loading: authLoading } = useAuth();
```

### 2. Replace Manual Fetch with Hooks
```typescript
// Before
useEffect(() => {
  const response = await fetch(`/api/get-approved-plays?teamId=${teamId}`);
  const data = await response.json();
  setPlays(data.plays);
}, [teamId]);

// After
const { plays, loading, error } = usePlays({ status: 'approved' });
```

### 3. Update Property Names
```typescript
// Before (snake_case)
play.formation_name
play.ai_insights
flashcard.question_prompt

// After (camelCase)
play.formationName
play.aiInsights
flashcard.questionPrompt
```

### 4. Simplify Loading States
```typescript
// Before
const [isLoading, setIsLoading] = useState(true);
const [isLoadingCards, setIsLoadingCards] = useState(false);

// After
const { loading: playsLoading } = usePlays();
const { loading: cardsLoading } = useFlashcards();
```

## Known Issues / Future Considerations

### 1. Metadata Structure
The old API returned detailed `playbook_metadata` with structured fields. The new API uses generic `metadata?: any`.

**Impact:** Playbook page may not display metadata sections if new API doesn't return expected structure.

**Mitigation:** All metadata access is optional, so page won't crash - sections just won't render.

**Future Work:**
- Verify metadata structure in new API
- Create proper Metadata interface instead of `any`
- Update metadata display logic if needed

### 2. Flashcard Hints Format
Old format: single `explanation` string
New format: `hints: string[]` array

**Current:** Quiz cards display all hints as bulleted list

**Future Consideration:** Add "show hint" button to reveal hints progressively
